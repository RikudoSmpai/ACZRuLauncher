# Модуль: русские строки из acz.exe

Маленькая DLL (`version.dll`), которую лаунчер кладёт рядом с `acz.exe` отдельной Steam-версии Zero.
Игра сама грузит её из своей папки, как любой `version.dll`. Модуль после старта игры заменяет **в памяти**
несколько английских строк из секции данных `.rdata` на русские. Файл `acz.exe` на диске не меняется.

## Что делает

Один фоновый поток, по шагам:

1. Если процесс — не `acz.exe`, ничего не делает. Журнал тоже не пишет.
2. Ждёт окно игры («ACE COMBAT…»), то есть полного старта. Не дождался за 5 минут — ничего не меняет.
3. Ищет рядом с игрой и папкой выше античит (EasyAntiCheat, BattlEye и т. п.). Нашёл — ничего не меняет.
4. Читает `settings\setting.ini`. Если там не `SystemLanguage=UK`, ничего не меняет: английский (US) остаётся
   английским.
5. Сверяет заголовок `acz.exe` в памяти (время сборки, размер образа, место `.rdata`). Затем сверяет **один
   sha256 всей таблицы** строк (всех групп, включая выключенные). Хоть одно расхождение (другая версия exe, Zero из AC8, чужая
   сборка) — ничего не меняет («всё или ничего»).
6. Для каждой строки включённой группы делает её страницу `.rdata` доступной на запись, пишет русские байты
   (только саму исходную строку с её нулём, см. «Правило записи») и возвращает прежнюю защиту. Ошибка на
   любой строке — уже записанные возвращаются к исходным.
7. Пишет журнал `%LOCALAPPDATA%\ACZRuLauncher\module.log` (перезаписывается при каждом запуске; ни путей,
   ни имени пользователя там нет) и завершается.

`DllMain` только отключает уведомления потоков и запускает этот поток.

## Чего не делает

- Не трогает код игры: `.text` и `.bind` модуль не читает и не пишет. Не ставит хуки и не меняет инструкции,
  таблицу импорта и точку входа. Не снимает дампы.
- Не трогает Steam: ничего не вызывает из Steam API, ничего не проверяет и не обходит, `steam_api64.dll`
  не подменяет и не оборачивает.
- Не грузит других DLL, кроме настоящего `version.dll`. Его модуль грузит по полному пути из
  `GetSystemDirectoryW` при первом вызове. Плагинов и «ASI-загрузчика» нет.
- Не ходит в сеть, не запускает процессы, не пишет в реестр. Импорт модуля — только `KERNEL32` и `USER32`,
  это проверяет `proxytest`.
- Английского текста игры здесь нет. Строки узнаются по RVA, длине слота и **одному sha256 всей таблицы** (см.
  ниже). Хэша отдельной строки или группы нет: одну-две короткие строки по их хэшу можно было бы подобрать
  перебором, всю таблицу из 29 строк — нет.

## Правило записи

Исходная строка длиной L занимает L+1 байт (с нулём). Нули после неё могут быть уже другими данными (пустая
строка, нулевая константа), поэтому:

- новый текст — не длиннее L+1 байт. Модуль пишет **только байты [0, L+1)** исходной строки: текст и нули
  до L+1;
- текст ровно из L+1 байт завершает ноль, который стоит сразу после строки. В оригинале он уже ноль (это
  покрывает хэш таблицы), модуль его не пишет;
- остальные байты слота после L+1 модуль не трогает.

`gen_header.py` и `patchtest` отказывают строке длиннее L+1.

## Хэш таблицы

`table_sha256` в `patches.json` — один sha256 по всем слотам таблицы (всех групп, включённых и нет) в порядке
таблицы. Для каждой строки подряд: `rva` (4 байта, little-endian), `slot` (2 байта, little-endian), затем `slot`
исходных байтов (строка и её нулевой хвост до следующих данных). Подмена любого байта любого слота ломает хэш
(`patchtest` проверяет это для каждого байта). Хэша на группу нет: в группе меток всего две короткие строки, их
хэш подбирается перебором. `gen_header.py` отказывает таблице с хэшем группы или строки.

## Почему `version.dll`

`acz.exe` импортирует его ради трёх функций (`GetFileVersionInfoSizeW`, `GetFileVersionInfoW`,
`VerQueryValueW`). Его нет в списке KnownDLLs, поэтому Windows сначала ищет его в папке программы.
Модуль экспортирует все 17 функций системного `version.dll` с теми же номерами. Каждая пересылается в настоящий.
Остальные кандидаты хуже. `winmm.dll` — около 180 экспортов. `XINPUT1_4.dll` — ввод, важен для игры.
`dinput8.dll` игра не импортирует. `steam_api64.dll` исключён правилами проекта.

## Файлы

| путь | что |
|---|---|
| `patches.json` | таблица: rva, L, слот, новые байты (L+1), группа, пометка ИИ; один sha256 всей таблицы. Английского текста нет |
| `tools/gen_header.py` | `patches.json` → `src/patches_gen.h`; `--check` — заголовок не устарел |
| `src/module.c` | `DllMain`, поток, проверки, журнал |
| `src/patch.c`, `patch.h` | сверка заголовка и хэшей, запись с откатом. Без вызовов Windows: тот же код идёт в тест |
| `src/proxy.c`, `version.def` | 17 экспортов `version.dll` |
| `src/sha256.c` | свой SHA-256: без лишней DLL (bcrypt) |
| `tests/patchtest.c` | тест таблицы на образе `acz.exe`, разложенном из файла |
| `tests/proxytest.c` | тест прокси: экспорты, пересылка, импорт, «не acz.exe — ничего» |
| `tests/gen_header_test.py` | `gen_header.py` отказывает испорченной таблице (текст длиннее L+1, хэш строки или группы, нет хэша таблицы, старый формат) |

## Сборка

```
module\build.cmd
```

Нужна Visual Studio 2022 или Build Tools с C++ x64. Python не обязателен: если он есть, сборка проверяет,
что `patches_gen.h` соответствует `patches.json`, и гоняет `tests\gen_header_test.py`. В `module\build\` появятся:

- `version.dll` — модуль. Лаунчер вшивает его в себя при сборке (`ACZRuLauncher.Core.csproj`). Если файла нет,
  лаунчер соберётся без модуля;
- `probe\version.dll` — пробная сборка, в ней включены все группы (см. ниже);
- `patchtest.exe`, `proxytest.exe`.

Сборка воспроизводимая (`/Brepro`): одинаковый исходник даёт одинаковые байты.

## Тесты

```
module\build\patchtest.exe                       синтетика: SHA-256, заголовок, правило записи, «всё или ничего», откат
module\build\patchtest.exe "<путь>\acz.exe"      + настоящая таблица на образе acz.exe
module\build\proxytest.exe module\build\version.dll
```

`patchtest` с путём читает из `acz.exe` только заголовки PE и сырые байты `.rdata`. Из них он раскладывает образ
по RVA, накладывает таблицу тем же кодом, что и модуль, и сверяет весь образ байт в байт. Меняться могут только
байты [0, L+1) строк включённых групп, и каждая запись запрашивается ровно на этот диапазон. Ещё он проверяет,
что каждый текст ≤ L+1, и что подмена любого байта любого слота ломает хэш таблицы. Игра при этом не запускается.

## Группы

| группа | строки | в релизе |
|---|---|---|
| `labels` | метки над целями и союзниками в HUD | да: шрифт (таблица h8) подтверждён кадром из игры |
| `result` | экран итогов миссии, подписи панели повтора | нет: каким шрифтом их рисует игра, кадром не подтверждено. Включаются только в `probe\version.dll` |

Русские буквы рисуются шрифтом HUD. Кириллица в таблице h8 появляется только из пакета перевода, в котором
есть фича `hud-font-h8-cyr` (`manifest.json` → `features`). Без неё лаунчер модуль не ставит. Коды букв — из
сборки шрифта real2: 15 частых букв на кодах `l…z` (игра берёт их запись по номеру: код − 0x3B), 7 редких
(Ё Ф Ц Щ Ъ Э Ю) на `! $ & ( ) * +` (игра ищет их по байту кода); двойники А В Е К М Н О Р С Т Х — латиницей.
Байты `patches.json` должны совпадать со шрифтом в пакете.

Включить группу — `"enabled": true` в `patches.json`, затем `python module\tools\gen_header.py` и `module\build.cmd`.
